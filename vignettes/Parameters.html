ProteoMaker Pipeline Parameters

This document describes the parameters used in the ProteoMaker pipeline. ProteoMaker generates in-silico bottom-up LC-MS datasets from proteoforms, from ground-truth proteoform generation through digestion, MS simulation, data analysis, and benchmarking.

Parameters are split into two groups:

  • set_proteomaker() controls paths, parallelization, and which downstream steps are run.
  • def_param() returns the simulation parameters used by the pipeline stages.

Summary

Configuration from set_proteomaker()

These settings are not part of the simulation parameter grid. They control where files are read and written, how much parallelism is used, and whether optional downstream steps run.

Parameter Default Purpose
fastaFilePath package Proteomes folder Directory containing FASTA files referenced by PathToFasta.
resultFilePath SimulatedDatasets Output directory for cached simulation stages and benchmark results.
cores 2 Number of CPU cores used by parallel steps.
clusterType PSOCK Parallel cluster backend, usually PSOCK or FORK.
runStatTests TRUE Run statistical tests after simulation.
calcAllBenchmarks TRUE Calculate benchmark summaries after statistical testing.

Using the Parameters

Use set_proteomaker() once for runtime configuration and def_param() for the simulation design.

Code 
config <- set_proteomaker(
  fastaFilePath = system.file("Proteomes", package = "ProteoMaker"),
  resultFilePath = file.path(tempdir(), "SimulatedDataSets"),
  cores = 1,
  clusterType = "PSOCK",
  runStatTests = TRUE,
  calcAllBenchmarks = TRUE
)

Param <- def_param()
Param$paramGroundTruth$PathToFasta <- "fasta_example.fasta"
Param$paramGroundTruth$NumCond <- 2
Param$paramGroundTruth$NumReps <- 3

Each top-level element in Param corresponds to one pipeline stage. Parameters can be vectors; run_sims() expands them into combinations.

def_param() Simulation Parameters

The detailed sections below follow the actual top-level lists returned by def_param(). Defaults and ranges are read from inst/config/parameters.yaml; the explanatory text adds the longer guidance from the original vignette.

paramGroundTruth: Ground Truth and Experimental Design

Define the input proteome, experiment layout, expressed proteins, and PTM ground truth.

Experimental Design

Param$paramGroundTruth$ProteoMakerVersion

Default: dev   Range: NA - NA   Class: string

Keeps the ProteoMaker version in the parameter set so cached simulation files can be traced back to the package version that generated them. This is set automatically by run_sims() and usually does not need to be changed manually.

Param$paramGroundTruth$NumCond

Default: 2   Range: 1 - 10   Class: numeric

Number of experimental conditions to simulate. For example, a treated-versus-control experiment has 2 conditions. This value defines the condition blocks used throughout the pipeline and is used together with NumReps to create quantitative column names.

Param$paramGroundTruth$NumReps

Default: 3   Range: 1 - 10   Class: numeric

Number of replicates per condition. Replicates may represent technical or biological replicates and are required for the downstream statistical tests. Increasing this value improves statistical stability but increases the size of every simulated dataset.

Input Data

Param$paramGroundTruth$PathToFasta

Default: fasta_example.fasta   Range: NA - NA   Class: file

Name of the FASTA file containing the protein sequences. ProteoMaker reads this file from the directory configured with set_proteomaker(fastaFilePath = ...). Standard UniProt FASTA files are supported; unusual header formats may require reformatting before simulation.

Param$paramGroundTruth$PathToProteinList

Default: NA   Range: NA - NA   Class: file

Optional file containing protein accessions to select for modification. Use this to focus PTM simulation on a predefined protein subset. If NA, modified proteins are sampled from the FASTA according to FracModProt.

Ground Truth Data

Param$paramGroundTruth$PercExpressedProt

Default: 1   Range: 0 - 1   Class: numeric

Fraction of proteins from the FASTA retained as the expressed proteome. The selection is random and mimics the fact that not every encoded protein is observed in a biological sample. The default 1 keeps all proteins.

Param$paramGroundTruth$FracModProt

Default: 0   Range: 0 - 1   Class: numeric

Fraction of modifiable proteins selected for PTM generation. Selection is made from all modifiable proteins, or from PathToProteinList if a protein list is supplied. Use 0 for no modified proteins and 1 to modify all eligible proteins.

Param$paramGroundTruth$PropModPerProt

Default: 1   Range: 1 - 500   Class: numeric

Multiplier for generating modified proteoforms per selected protein. A value of 1 creates one modified proteoform per selected protein. Values greater than 1 create additional independently modified proteoforms from the selected protein pool.

Param$paramGroundTruth$PTMMultipleLambda

Default: 0   Range: 0 - 10   Class: numeric

Controls the average number of modification sites per proteoform via a truncated Poisson distribution over the available modifiable sites. Values of 0 or values less than or equal to 1e-4 are clamped internally and usually produce approximately one modified site per PTM type per proteoform. Larger values increase multi-site modification.

Param$paramGroundTruth$RemoveNonModFormFrac

Default: 0   Range: 0 - 1   Class: numeric

Fraction of selected modifiable proteins for which the unmodified proteoform is removed. The default 0 keeps unmodified counterparts, which is useful for occupancy estimation. Setting this to 1 removes all unmodified counterparts for selected proteins.

Param$paramGroundTruth$PTMTypes

Default: NA   Range: NA - NA   Class: ptm

PTM types to simulate. Use the list form list(mods = c("ph", "ac")); the mods element is required. Names are arbitrary but must be used consistently in PTMTypesMass, PTMTypesDistr, ModifiableResidues, and ModifiableResiduesDistr.

Param$paramGroundTruth$PTMTypesDistr

Default: NA   Range: 0 - 1   Class: ptm

Relative frequency of each PTM type among all simulated PTMs. Provide a named list with values that sum to 1, for example list(ph = 1) for phosphorylation only or list(ph = 0.8, ox = 0.2) for mixed PTMs.

Param$paramGroundTruth$PTMTypesMass

Default: NA   Range: 0 - 200   Class: ptm

Mass shift for each PTM type, provided as a named list such as list(ph = 79.966331). This must be set when PTMs are enabled. Values can use UniMod masses or any custom mass shifts needed for the simulation.

Param$paramGroundTruth$ModifiableResidues

Default: NA   Range: NA - NA   Class: ptm

Residues on which each PTM type can occur. For phosphorylation, this is usually list(mods = list(ph = c("S", "T", "Y"))). Each PTM type should have a matching residue vector.

Param$paramGroundTruth$ModifiableResiduesDistr

Default: NA   Range: 0 - 1   Class: ptm

Relative residue frequencies for each PTM type. For phosphorylation, a common setup is S = 0.86, T = 0.13, and Y = 0.01. These values bias site selection among the residues listed in ModifiableResidues.

paramProteoformAb: Proteoform Abundance

Generate quantitative proteoform abundances and regulation patterns.

Proteoform Quantities

Param$paramProteoformAb$QuantNoise

Default: 0.5   Range: 0 - 5   Class: numeric

Standard deviation of log2 noise added to quantitative proteoform values. The default 0.5 introduces moderate technical and biological variability.

Param$paramProteoformAb$DiffRegFrac

Default: 0.3   Range: 0 - 1   Class: numeric

Fraction of proteoforms marked as differentially regulated. Use this to control how many true abundance changes are present in the simulated experiment.

Param$paramProteoformAb$DiffRegMax

Default: 1   Range: 0 - 10   Class: numeric

Maximum absolute log2 fold-change amplitude assigned to regulated proteoforms. Larger values create stronger regulation effects.

Param$paramProteoformAb$UserInputFoldChanges_NumRegProteoforms

Default: 0   Range: 0 - 1000   Class: numeric

Optional override for the number of regulated proteoforms. The default 0 disables the override and uses DiffRegFrac instead.

Param$paramProteoformAb$UserInputFoldChanges_RegulationFC

Default: 0   Range: -10 - 10   Class: numeric

Optional override for the fold change applied to user-specified regulated proteoforms. The default 0 disables this override.

Param$paramProteoformAb$AbsoluteQuanMean

Default: 30.5   Range: 0 - 100   Class: numeric

Mean absolute protein abundance before proteoform-level distribution. Proteoform abundances are distributed from the protein-level abundance so that proteoforms sum back to the parent protein abundance.

Param$paramProteoformAb$AbsoluteQuanSD

Default: 3.6   Range: 0 - 10   Class: numeric

Standard deviation of absolute protein abundance. This controls variability in the baseline abundance distribution before proteoform-level splitting.

Param$paramProteoformAb$ThreshRemoveProteoforms

Default: 0   Range: 0 - 100   Class: numeric

Threshold for removing low-abundance proteoform quantitative values when absolute quantification is enabled. Values below this threshold are removed.

paramDigest: Digestion and Sample Preparation

Digest proteoforms and optionally simulate PTM enrichment or sample preparation losses.

Enzymatic Digestion

Param$paramDigest$Enzyme

Default: trypsin   Range: NA - NA   Class: string

Protease used for in-silico digestion. The default is trypsin. Other supported rules include trypsin.strict, chymotrypsin.h, chymotrypsin.l, pepsin.2, pepsin.1.3, lysC, and argC.

Supported enzyme definitions used by the digestion code:

Enzyme Cleavage rule Regex
trypsin K or R, except KP/RP (?!(RP|KP))(?=(K|R))(?!(K|R)$)
trypsin.strict K or R, including KP/RP (?=(K|R))(?!(K|R)$)
chymotrypsin.h F, Y, or W; high specificity exclusions (?!(FP|YP|PY|WP))(?=(F|Y|W))(?!(F|Y|W)$)
chymotrypsin.l F, Y, W, L, or P; broader specificity exclusions (?!(FP|YP|PY|WP|LP|MP))(?=(F|Y|W|L|P))(?!(F|Y|W|L|P)$)
pepsin.2 F, L, W, Y, A, E, or Q (?=(F|L|W|Y|A|E|Q))(?!(F|L|W|Y|A|E|Q)$)
pepsin.1.3 F or L (?=(F|L))(?!(F|L)$)
lysC K (?=(K))(?!(K)$)
argC R, except RP (?!(RP))(?=(R))(?!(R)$)
Param$paramDigest$PropMissedCleavages

Default: 0.01   Range: 0 - 1   Class: numeric

Additional fraction of peptides simulated with missed cleavages. This introduces incomplete digestion beyond the fully cleaved peptide set.

Param$paramDigest$MaxNumMissedCleavages

Default: 2   Range: 0 - 10   Class: numeric

Maximum number of missed cleavages allowed per peptide. Higher values increase the number and length range of possible peptides.

Param$paramDigest$PepMinLength

Default: 7   Range: 1 - 50   Class: numeric

Minimum peptide length retained after digestion. Short peptides are often difficult to identify reliably and are filtered out.

Param$paramDigest$PepMaxLength

Default: 30   Range: 1 - 60   Class: numeric

Maximum peptide length retained after digestion. Very long peptides may fall outside practical MS detection or search ranges.

Param$paramDigest$LeastAbundantLoss

Default: 0   Range: 0 - 1   Class: numeric

Fraction of least abundant peptides removed after peptide summarisation. This simulates systematic loss of weak peptide signals and is an alternative to fixed abundance thresholding.

Sample Preparation

Param$paramDigest$EnrichPTM

Default: NA   Range: NA - NA   Class: string

PTM type to enrich during sample preparation. Only one PTM can be enriched at a time. The default NA disables enrichment and no enrichment fraction is created.

Param$paramDigest$EnrichmentLoss

Default: 0.2   Range: 0 - 1   Class: numeric

Fraction of peptides lost during enrichment. This models sample handling and enrichment inefficiency.

Param$paramDigest$EnrichmentEfficiency

Default: 1   Range: 0 - 1   Class: numeric

Efficiency of enrichment for modified peptides. The implementation removes non-modified peptides until the requested fraction of modified peptides is reached.

Param$paramDigest$EnrichmentQuantDiff

Default: 0   Range: -10 - 10   Class: numeric

Mean log-scale intensity difference introduced between enriched modified peptides and non-modified peptides. Use this to model quantitative shifts caused by enrichment.

Param$paramDigest$EnrichmentNoise

Default: 0.2   Range: 0 - 10   Class: numeric

Additional noise introduced by the enrichment protocol.

Param$paramDigest$ModificationLoss

Default: 0   Range: 0 - 1   Class: numeric

Fraction of modified peptides removed from non-enriched samples during sample preparation.

paramMSRun: MS Run and Search

Simulate detection, missing values, instrument noise, false IDs, and localization errors.

MS Run

Param$paramMSRun$PercDetectability

Default: 0.25   Range: 0 - 1   Class: numeric

Fraction of peptides retained by the PeptideRanger detectability model. For example, 0.25 keeps the top 25 percent most detectable peptides.

Param$paramMSRun$PercDetectedVal

Default: 0.5   Range: 0 - 1   Class: numeric

Fraction of peptide intensity values retained per replicate and condition. Values not retained become missing values.

Param$paramMSRun$WeightDetectVal

Default: 1   Range: 0 - 50   Class: numeric

Controls how strongly intensity affects missingness. Higher values make low-intensity peptides more likely to be missing.

Param$paramMSRun$MSNoise

Default: 0.25   Range: 0 - 1   Class: numeric

Gaussian noise added to peptide intensities to mimic instrument variability. Values are on the log2 scale.

MS Search

Param$paramMSRun$WrongIDs

Default: 0.01   Range: 0 - 0.1   Class: numeric

Fraction of peptide identifications replaced by wrong identifications. This models false peptide IDs from database search.

Param$paramMSRun$WrongLocalizations

Default: 0   Range: 0 - 0.1   Class: numeric

Fraction of PTM-bearing identifications with incorrect PTM site localization. Affected peptides are flagged through the localization columns.

MS Search Results Filter

Param$paramMSRun$MaxNAPerPep

Default: 100   Range: 0 - 100   Class: numeric

Maximum number of missing values allowed per peptide before filtering. Higher values keep peptides with more missingness.

paramDataAnalysis: Data Analysis

Control protein summarisation and statistical testing.

Protein Summarization

Param$paramDataAnalysis$SharedPep

Default: FALSE   Range: FALSE - TRUE   Class: boolean

Whether shared peptides can be used in protein summarisation. Shared peptides can increase coverage but may make protein-level interpretation less specific.

Param$paramDataAnalysis$ProtSummarization

Default: medpolish   Range: NA - NA   Class: string

Method used to aggregate peptide intensities into protein groups. Choices are sum.top3, medpolish, median, mean, sum, and rlm. The sum methods operate on the intensity scale before returning log2 values.

Param$paramDataAnalysis$MinUniquePep

Default: 1   Range: 1 - 10   Class: numeric

Minimum number of unique peptides required for protein summarisation. Proteins with fewer unique peptides are skipped.

Param$paramDataAnalysis$IncludeModPep

Default: FALSE   Range: FALSE - TRUE   Class: boolean

Whether modified peptides contribute to protein summarisation. The default FALSE excludes PTM-bearing peptides from protein abundance summarisation.

Statistical Testing

Param$paramDataAnalysis$StatPaired

Default: FALSE   Range: FALSE - TRUE   Class: boolean

Whether downstream statistical testing uses a paired design. Set this according to the experimental design being simulated.

PTM Setup Recipe

This minimal phosphorylation setup keeps the unmodified counterpart and creates approximately one modified site per modified proteoform.

Code 
Param$paramGroundTruth$FracModProt <- 0.5
Param$paramGroundTruth$PTMTypes <- list(mods = c("ph"))
Param$paramGroundTruth$PTMTypesMass <- list(ph = 79.966331)
Param$paramGroundTruth$PTMTypesDistr <- list(ph = 1)
Param$paramGroundTruth$ModifiableResidues <- list(mods = list(ph = c("S", "T", "Y")))
Param$paramGroundTruth$ModifiableResiduesDistr <- list(
  mods = list(ph = c(S = 0.86, T = 0.13, Y = 0.01))
)
Param$paramGroundTruth$PTMMultipleLambda <- 0
Param$paramGroundTruth$PropModPerProt <- 1
Param$paramGroundTruth$RemoveNonModFormFrac <- 0

Practical Notes

  • Use set_proteomaker() for filesystem and runtime settings.
  • Use def_param() for anything that should define a simulated dataset.
  • Keep small parameter grids while testing; each vector-valued parameter multiplies the number of simulations.
  • PathToFasta names a FASTA file, while fastaFilePath names the directory that contains it.
  • The old commented PercDetectedPep entry is not part of the current parameter set; use PercDetectability and PercDetectedVal.
